# existing-scanners

## SUMMARY
There is already a crowded field of skill/MCP scanners (verified via gh on 2026-09-18). The serious ones are Python and hybrid: NVIDIA/SkillSpector (17.7k stars, Apache-2.0, has a fully static --no-llm mode with supply-chain SC1-SC9 and rug-pull RP1-RP3 rules), cisco-ai-defense/skill-scanner (2.5k stars, Apache-2.0, YAML signatures + YARA-X + AST dataflow, LLM optional), snyk/agent-scan (3k stars, Apache-2.0 client but needs SNYK_TOKEN and a cloud analysis API, so not deterministic/offline), Tencent/AI-Infra-Guard skill-scan (LLM API key required). The three skills.sh auditors (Gen, Socket, Snyk) and ClawHub's VirusTotal Code Insight are all cloud + LLM. None is a drop-in for a TypeScript, offline, deterministic gate. The best directly reusable assets for AgentPM are rule CORPORA, not engines: (1) Agent-Threat-Rule/agent-threat-rules (MIT, TypeScript reference engine, npm package `agent-threat-rules` with only js-yaml + MCP SDK deps, 825 YAML regex rules incl. 52 skill-compromise rules such as ATR-2026-00126 'Skill Rug Pull Setup'), (2) gendigitalinc/sage `threats/*.yaml` (TypeScript project, 200+ regex rules under the permissive Detection Rule License 1.1), (3) Cisco's `skill_scanner/data/packs/core/signatures/*.yaml` and NVIDIA's SC/RP regex tables (both Apache-2.0, portable to TS with attribution). Critical caveat backed by three independent 2026 sources (Trail of Bits, Air Security, OWASP AST05/AST08): every content scanner, including Cisco, NVIDIA and all skills.sh auditors, was bypassed, and the bypass that matters most for the owner's worry is exactly the mutable external target: the payload lives at a URL the scanner never fetches and is swapped after approval (~26,000 agents affected in Air Security's demo). So pattern scanning cannot be the primary control for rug pulls; the deterministic controls that actually work are structural: extract and inventory every external reference, classify each as immutable (commit SHA, sha256 digest, exact version + integrity) or mutable (branch/tag, @latest, bare URL, releases/latest, curl|sh, remote MCP, symlink escaping the package), gate on mutable ones, pin content hashes in a lockfile, and diff the 'capability surface' on update (the approach of skills-lock/skil-lock, T-Zevin/SkillGuardrail, ramparts drift detection, and SkillSpector's baseline). Recommended shape: own TS engine in a new package, vendored/ported rule packs with attribution, optional shell-out adapters to SkillSpector/Cisco/ATR CLI when installed, and optional advisory lookup of the skills.sh audit endpoint for GitHub sources.

## RECOMMENDATIONS
- Build the gate as AgentPM's own pure-TypeScript engine in a new package (for example packages/security) rather than depending on any existing scanner: every mature engine is Python and/or cloud/LLM, and the deterministic cores of even the best ones report low recall (Cisco: 7.75% recall on a source-disjoint split). Expose it to install/update/sync/pull, to push/registry publish, and to the registry server upload handler through one function that returns findings plus a PASS/REVIEW/BLOCK verdict.
- Make structural, non-heuristic controls the primary defense against the owner's rug-pull worry, because three independent 2026 sources (Trail of Bits, Air Security, OWASP AST05/AST08) show content scanners cannot see a payload that lives at a mutable external target. Deterministically extract an external-reference inventory from every file (URLs, git refs, npx/uvx/pip/docker invocations, curl|wget pipes, remote MCP server URLs, remote includes, releases/latest links, symlinks) and classify each as immutable (40-hex commit SHA, sha256 digest, exact version with integrity) or mutable (branch, tag, @latest or no version, bare URL, releases/latest). Gate on mutable references that the skill tells the agent to fetch-and-follow or fetch-and-execute; store the inventory in the install record.
- Pin what was reviewed: record a sha256 over a deterministic packaging of the skill (stable file order, no timestamps) plus the resolved commit SHA in AgentPM's db/manifest and in agentpm.yaml lock data; refuse sync/update when content drifts from the pin without an explicit confirmation; on the registry server make versions immutable (same name+version must have the same digest) and re-verify the digest on download. Prior art: SkillGuardrail receipts, ClawHub deterministic packaging, OWASP AST07 mitigation 1.
- Add a capability-surface diff on update, modeled on skills-lock/skil-lock: extract sets of shell commands, network hosts, file paths read/written, allowed-tools, bundled scripts and external references; on update/sync/pull show only the delta and require confirmation for additions (new host, new curl, new .env read, new mutable reference). This turns 'something changed' into 'this is what the skill can now do' and is fully deterministic.
- Fail closed on anything not analyzable, since that is how every scanner was bypassed: walk every file in the package (not only those referenced by SKILL.md), including dotfiles; flag binaries, .pyc/__pycache__, archives and OOXML documents, file-magic vs extension mismatch, symlinks (especially ones resolving outside the package root), oversize files and extreme whitespace padding; never truncate silently, and report a coverage figure. Copy resource bounds from SkillSpector (100 MiB ingest, 10,000 members, depth 3, 100:1 ratio).
- Seed the pattern layer by vendoring or porting rule corpora with attribution instead of writing rules from scratch, in this order: (1) Agent Threat Rules (MIT, YAML regex, TS-native; pin a version, load only scan_target skill/mcp, translate inline (?i) flags, start in warn mode because skill rules are maturity: test; do not enable its Threat Cloud reporter); (2) Gen Sage threats/*.yaml (DRL 1.1, keep author + link); (3) NVIDIA SkillSpector SC1-SC9 and RP1-RP3 regex tables and Cisco core signature YAMLs plus the regex strings of their YARA rules (both Apache-2.0, keep notices). Avoid Nova (GPL-3.0) and unlicensed repos (alonw0/secure-skills scanner code, Teycir/SkillsGuard, trailofbits test skills).
- Run every text rule over three views like ramparts does: raw, normalized (strip zero-width/bidi/tag characters, NFKC fold, collapse padding) and iteratively base64/hex-decoded; separately flag the presence of invisible Unicode, HTML comments containing imperative text, and homoglyph names as findings of their own.
- Make rules Markdown-aware to keep false positives low, as Cisco's active_remote_execution.py and Sage's macros do: distinguish operative instructions from code fences, quoted examples, negated statements and 'anti-pattern / do not' sections, and keep an evidence anchor (file, line, snippet) on every finding. Follow SkillTotal's split: evidenced findings affect the verdict, unevidenced hints go to a needs_review list that does not.
- Adopt SkillGuardrail's and SkillSpector's baseline semantics for accepted risk: an acceptance is bound to the package fingerprint and finding key, carries a reason and expiry, never applies to High/Critical, and becomes void when the content changes. Keep AgentPM's existing rule that install scripts are reported, never executed, and extend it: the scanner must never execute, import or render scanned content.
- Offer existing scanners only as optional adapters, never as the gate: if `skillspector`, `skill-scanner` or `atr` is on PATH, allow `agentpm scan --engine <name>` to shell out in static mode (`skillspector scan --no-llm --format sarif`, `skill-scanner scan --format sarif`) and merge SARIF results as advisory findings. Do not shell out to snyk agent-scan by default (needs a token, cloud analysis, and it executes MCP server commands).
- Optionally add an opt-in advisory lookup of skills.sh audit verdicts for public GitHub sources via the same endpoint the skills CLI uses, clearly labelled as third-party, non-deterministic, disabled for private sources and never blocking when offline. Treat it as unofficial API surface that can change.
- Use public malicious corpora as regression targets for the gate without vendoring them: trailofbits/overtly-malicious-skills (4 bypass skills), the Cisco `evals/skills/` fixtures (Apache-2.0), SkillSpector test fixtures, and ATR's embedded true/false-positive test cases (which can be run directly as unit tests for ported rules). Tag every AgentPM finding with OWASP Agentic Skills Top 10 ids (AST01-AST10) and, for mutable targets, reuse Snyk's category names `unverifiable_dependencies` and `third_party_content_exposure` so results are comparable with other tools.

## CORRECTIONS (partly/refuted/unverifiable)
- [partly] NVIDIA SkillSpector has a fully static --no-llm mode with supply-chain rules SC1-SC9 and rug-pull rules RP1-RP3, in the named files, plus baselines, ingest caps and nested-artifact limits.
  -> Two nuances the researcher understated. (1) '--no-llm' is NOT offline or fully reproducible: README says SC4 'sends dependency names to OSV.dev ... runs even with --no-llm', so results vary with OSV state unless the network is blocked (then a small static fallback list is used). (2) LLM analysis is ON by default and sends file contents to the configured provider; a shell-out adapter must always pass --no-llm. Also the README rule table omits SC7 (it exists only in source).
- [partly] Agent Threat Rules: MIT, TypeScript, npm package agent-threat-rules v4.1.0 with only js-yaml + @modelcontextprotocol/sdk runtime deps, 825 rules in 10 categories (prompt-injection 250, tool-poisoning 113, context-exfiltration 133, skill-compromise 52), named rule files exist, `atr convert generic-regex`, Cisco vendors 712 rules, all 38 scan_target:skill rules are maturity:test (0 of 32 detected in enforce lane), optional Threat Cloud reporter defaulting to tc.panguard.ai, single maintainer.
  -> The npm registry 'latest' dist-tag is 4.0.0 (published 2026-08-23), not 4.1.0; 4.1.0 exists only in the repo's package.json and is unpublished as of 2026-09-18 (https://registry.npmjs.org/agent-threat-rules). Pin 4.0.0 or a git SHA. Cisco vendored 3.5.6, an older major. Also the Cisco pack README warns the ATR 'PINT' benchmark is self-built and 226 of 272 detections come from one rule, which supports the researcher's 'heavy marketing claims' caveat.
- [partly] Gen Sage threats/*.yaml is a TypeScript-project regex corpus of 200+ rules under Detection Rule License 1.1 with macros and a trusted-installer-domain list; prompt-injection.yaml is tier-1 'zero model dependency, ~1ms'.
  -> Reuse value for an install-time scanner is lower than implied. In the cross-platform files 51 rules are match_on: command, 20 file_path, 5 url and only 39 (+4 mixed) match on content; supply_chain.yaml contains exactly ONE rule (curl|wget ... install | sh, match_on: command). The corpus is written for runtime tool-call interception, so to use it statically AgentPM must first extract commands from code fences/scripts and feed those to the command rules. The 29 prompt-injection content rules are the directly portable part. About 140 of the rules are win-/mac- specific command rules.
- [partly] Trail of Bits (2026-06-03) bypassed ClawHub, Cisco skill-scanner and the skills.sh auditors 'in under an hour each' via 100,000 newlines, hidden .docx, poisoned .pyc and LLM-judge prompt injection; scanners ignore hidden files/binaries/unreferenced files; test corpus repo has 4 skills and no license.
  -> Timing is wrong as stated: it was under one hour TOTAL for three of the four skills, and 'a few hours' for the fourth (prompt-injection) one. The 'each in under an hour' wording comes from OWASP AST08's paraphrase, not from Trail of Bits. NVIDIA SkillSpector was NOT tested by Trail of Bits (only by Air Security). ToB's own recommendation is curated collections + version pinning + treating public skills as untrusted code, not better scanning.
- [partly] No existing scanner is a drop-in for a deterministic, offline, TypeScript gate; the best reusable assets are rule corpora, and AgentPM should build its own TS engine.
  -> The conclusion still holds (agentshield audits an agent's installed configuration rather than gating a skill package, and aguara is Go), but 'none is TypeScript/MIT' is too strong: agentshield is the largest TS/MIT deterministic rule base in this space and its hook/MCP rules (SessionStart download-and-execute, 'npx -y' auto-install, remote MCP transport, shell metacharacters in MCP args) are directly relevant to scanning Claude/Codex PLUGINS, which AgentPM now installs. It should be evaluated ahead of several of the 2-15 star repos listed.

## FINDINGS
### No existing scanner is a drop-in for a deterministic, offline, TypeScript gate; the mature engines are Python and hybrid [high]
Verified with gh api on 2026-09-18: NVIDIA/SkillSpector (Python, Apache-2.0, 17,750 stars, pushed 2026-09-18), cisco-ai-defense/skill-scanner (Python + Go CEL helper, Apache-2.0 per LICENSE file although GitHub reports NOASSERTION, 2,533 stars, pushed 2026-09-05), snyk/agent-scan (Python, Apache-2.0, 3,064 stars; invariantlabs-ai/mcp-scan now redirects to it), Tencent/AI-Infra-Guard (Python, Apache-2.0, 6,441 stars). SkillSpector and Cisco both have a genuinely deterministic core (`skillspector scan --no-llm`; Cisco 'core analyzers: static + bytecode + pipeline + correlation') with LLM as an optional layer. Snyk agent-scan requires SNYK_TOKEN and calls a versioned cloud 'analysis API' (2025-09-02 / 2026-07-10), and its README warns that scanning MCP configs executes the configured server commands. Tencent's aig-skill-scan requires LLM_API_KEY. Bitdefender/Agent-Skill-Scanner extracts indicators locally but the report is produced by a server-side LLM. For AgentPM this means: shell-out is only viable as an optional extra (Python/uv dependency, not pure Node), and the core gate must be our own TS code fed by ported rules.

### Agent Threat Rules (ATR) is the most reusable asset: MIT, TypeScript engine, YAML regex rules, already consumed by Cisco [high]
Agent-Threat-Rule/agent-threat-rules: MIT, TypeScript, 393 stars, pushed 2026-09-18, npm package `agent-threat-rules` v4.1.0 (node >=18, runtime deps only `js-yaml` and `@modelcontextprotocol/sdk`). 825 rules in `rules/<category>/ATR-YYYY-NNNNN-*.yaml` across 10 categories (prompt-injection 250 files, tool-poisoning 113, context-exfiltration 133, skill-compromise 52, ...). Rules carry `scan_target: skill|mcp`, `detection.conditions[]` with `operator: regex`, severity, maturity, embedded true/false-positive test cases, and measured wild FP rates. Directly relevant rules: `rules/skill-compromise/ATR-2026-00126-skill-rug-pull-setup.yaml` (eval(fetch()), base64-decode-exec, post-install curl, 'fetch config/instructions from https://...'), `ATR-2026-00065-skill-update-attack.yaml`, `ATR-2026-00128-html-comment-hidden-payload.yaml`, `ATR-2026-00129-unicode-smuggling.yaml`, `ATR-2026-00135-exfil-url-in-instructions.yaml`, `ATR-2026-00523-claude-code-hooks-session-start-pre-trust-rce.yaml`. `atr convert generic-regex` exports all patterns as JSON. Cisco vendors it as a pack (`skill_scanner/data/packs/atr/`, 712 rules, MIT) which is proof the license/format is vendorable. Caveats: (a) patterns use PCRE-style inline `(?i)` which JS RegExp does not accept natively, so a loader must translate flags; (b) the rule's own description admits 'true rug pull detection requires comparing hashes over time'; (c) the Cisco pack README notes all 38 `scan_target: skill` rules are `maturity: test`, so an 'enforce/stable only' load detects 0 of 32 malicious SKILL.md samples; (d) the repo contains an optional 'Threat Cloud' reporter (`src/tc-reporter.ts`, default endpoint tc.panguard.ai) that AgentPM should not adopt; (e) single-maintainer governance and heavy marketing claims, so pin a version and review rules before enabling blocking severity.

### NVIDIA SkillSpector has the most complete deterministic treatment of supply-chain and rug-pull patterns (portable regex tables) [high]
Files worth porting (Apache-2.0, keep NOTICE/attribution): `src/skillspector/nodes/analyzers/static_patterns_supply_chain.py` defines SC1 unpinned deps (bare names, >=, '*', 'latest', ^ranges, prose 'install the latest'), SC2 remote fetch-and-execute (curl|wget piped to sh/python/node, download-then-exec, exec(requests.get()), eval(fetch()), new Function(fetch())), SC3 decode-and-execute/obfuscation, SC4 OSV.dev lookup with offline static fallback, SC5 abandoned deps, SC6 typosquatting (edit distance vs popular packages), SC7 container trust bypass flags, SC8 shipped .pyc/__pycache__, SC9 executables concealed in documents/hidden artifacts. `mcp_rug_pull.py` defines RP1 unpinned `npx pkg`, `uvx pkg`, `pip install pkg`, `docker pull/run image` checked against `_VERSION_PIN_RE = @[\d.]+|==[\d.]+|:[\d.]+|@sha256:`, RP2 permission pre-staging, RP3 unpinned skill version, plus manifest-diff findings against a previous manifest (privilege expansion, trigger change, parameter change). Also `whitespace_padding.py` and `artifact_integrity.py` (letter-spacing, confusables, default-ignorable Unicode) and `docs/NESTED_ARTIFACT_INSPECTION.md` (DOCX/XLSX/PPTX/ZIP inspected in memory, links never followed, depth 3, 1,000 members, 25 MiB, 100:1 ratio, fail-closed). Ingest caps: 100 MiB, 10,000 zip members, 1 MB per-file analysis cap. It supports evidence-bound fingerprint baselines (`skillspector baseline`). NVIDIA uses it inside a 'Verified Skills' pipeline that scans then signs skills before publication, which is the same two-gate shape AgentPM wants. ### Cisco skill-scanner: good rule-pack layout to copy, but its own published numbers show how weak signature scanning is [high]
Rule files: `skill_scanner/data/packs/core/signatures/*.yaml` (command_injection, data_exfiltration, hardcoded_secrets, obfuscation, prompt_injection, supply_chain, social_engineering, unauthorized_tool_use, ...; schema = id, category, severity, patterns[], file_types[], description, remediation), `skill_scanner/data/packs/core/yara/*.yara` (16 YARA-X rules incl. `indirect_prompt_injection_generic.yara` which matches 'follow the instructions in/from the url/webpage/document', `prompt_injection_unicode_steganography.yara`, `coercive_injection_generic.yara`, `tool_chaining_abuse_generic.yara`), Python rules in `skill_scanner/core/rules/` (`active_remote_execution.py` = bounded Markdown-aware 'acquire + execute' grammar that skips code fences, negations and anti-pattern/example sections; `unicode_smuggling.py`; `ooxml_relationships.py`; `active_html_injection.py`), policy presets `skill_scanner/data/{default,strict,permissive}_policy.yaml`, packs for ATR and 'promptguard' (markdown_exfiltration, pii, secret_providers). Static analyzer also checks dependency pinning across many ecosystems, manifest-vs-behavior consistency and allowed-tools. YARA itself is not usable from pure Node without a native/wasm dependency, but the YARA string sections are plain regexes that port to TS. The README's own evaluation: on a locked source-disjoint split the deterministic core gets 60.75% precision, 7.75% recall, 13.74% F1 (dev benchmark: 99.16% precision, 31.43% recall). The README states 'No findings ≠ no risk'. Treat ported signatures as a tripwire layer, never as a safety certificate.

### Every content scanner has been publicly bypassed; the mutable-external-target bypass is the one that matters for the owner's worry [high]
Trail of Bits (2026-06-03) bypassed ClawHub (VirusTotal Code Insight + guard model), Cisco skill-scanner and the skills.sh auditors in under an hour each: 100,000 leading newlines caused truncation; payload in a hidden .docx (ZIP of XML); poisoned .pyc bytecode that differs from the benign .py; 'corporate artifact mirror' prose that talks an LLM judge into rating an npm-registry override as LOW; scanners only reading files referenced from SKILL.md and ignoring hidden files, binaries and images. Test corpus: trailofbits/overtly-malicious-skills (4 skills; no license file, so use only as a manual regression target, do not vendor). Air Security 'The Story of Skills' (2026-06-22): a skill whose payload lived at an attacker-controlled documentation URL (look-alike domain) was rated safe by Cisco's, NVIDIA's and all skills.sh scanners because none fetch external references; content was switched after trust was established; ~26,000 agents affected. OWASP Agentic Skills Top 10 v1.0 codifies this as AST05 'Untrusted External Instructions' (author rug-pull, reviewer bait-and-switch keyed on IP/user-agent, transitive reference chaining) and AST07 'Update Drift' (incl. Air Security 'SkillJacking': a deleted GitHub owner account re-registered to take over a skill with 11,483 installs; binaries from `releases/latest`). AST08 'Poor Scanning' mitigation 7: scan every file exhaustively, including hidden files, .pyc, archives and images, normalize padding and never truncate. Deterministic implication for AgentPM: fail closed on anything not analyzable (oversize, binary, archive, bytecode, truncation), and treat any external reference as unverifiable by design rather than trying to judge its content.

### Prior art for the real fix: capability-surface lockfiles, source-bound receipts and drift detection (all deterministic) [high]
skills-lock/skil-lock (Go, Apache-2.0, 6 stars, pushed 2026-09-09; SPEC.md is CC BY 4.0): parses SKILL.md + bundled scripts into sets (shell commands, network URLs/hosts, file reads/writes, allowed tools, bundled scripts), commits them to `skills.lock`, and on change shows a capability delta ('added network_urls https://... host not in allowed_domains', 'added file_reads ./.env matches protected_paths') that blocks until an approval entry with reviewer/reason is committed. Their scan of 17,065 public skills: 38.8% run shell commands, 4.0% declare it. T-Zevin/SkillGuardrail (Go, Apache-2.0, 57 stars, pushed 2026-08-18): quarantine -> static scan -> PASS/REVIEW/BLOCK/CRITICAL -> atomic install; resolves remote sources to an immutable commit before inspection, binds the approval to source commit + package fingerprint + external receipt, `verify` detects later drift, reviewed-findings baseline only valid for a matching fingerprint and never for High/Critical, fails closed on incomplete scans. highflame-ai/ramparts (Rust, Apache-2.0, 96 stars): content-fingerprints MCP configs, tool definitions and skill files against a stored baseline (`SkillContentChanged`, `MCPToolChanged`), re-runs YARA over a normalized view (zero-width stripped, NFKC homoglyph fold) and iteratively base64/hex-decoded views, flags undeclared network egress (manifest vs script mismatch) and builds an external-reference inventory; YARA rules in `rules/pre/skill_*.yar`. ATR ships a runtime `src/skill-fingerprint.ts` for behavior drift. ClawHub's pipeline starts with deterministic packaging (stable ZIP, fixed timestamps) and SHA-256 of the bundle, then daily re-scan. These map one-to-one onto AgentPM's manifest/db records and the registry server's JSON archives.
Sources: https://github.com/skills-lock/skil-lock ; https://github.com/T-Zevin/SkillGuardrail ; https://github.com/highflame-ai/ramparts ; https://github.com/Agent-Threat-Rule/agent-threat-rules/blob/main/src/skill-fingerprint.ts ; https://openclaw.ai/blog/virustotal-partnership

### skills.sh audits (Gen, Socket, Snyk) and ClawHub/VirusTotal are cloud + LLM services; usable only as optional advisory signals [medium]
Vercel announced on 2026-02-17 that skills.sh shows independent audits from Gen Agent Trust Hub, Socket and Snyk for 60,000+ skills, surfaced in the CLI since skills@1.4.0; flagged skills are hidden from search/leaderboard. Socket: static code analysis engine plus LLM detection over natural-language instructions, skill source is uploaded to Socket's API when installed via the CLI, and updated skills are re-scanned (claimed 94.5% precision / 98.7% recall on 382 malicious + 355 benign). Snyk: 'multiple customized LLM-based judges with deterministic rules', triggered from Vercel's infra on install, re-evaluated as detection improves. Gen: cloud-based AI classification. The vercel-labs/skills CLI (MIT, 31,956 stars) fetches results from `https://add-skill.vercel.sh/audit?source=<owner/repo>&skills=<slug,...>` with a 3 s timeout and never blocks on failure (`src/telemetry.ts`, `fetchAuditData`, response shape Record<skill, Record<auditor, {risk, alerts?, score?, analyzedAt}>>). This endpoint is undocumented/unofficial, covers only GitHub-sourced skills listed on skills.sh, sends the repo and skill names to Vercel, and the audits page gives no re-scan cadence. AgentPM already bridges to `npx skills`, so an opt-in advisory lookup is cheap, but it cannot be part of the deterministic gate and must be disabled for private sources. ClawHub (2026-02-07): SHA-256 of deterministic bundle -> VirusTotal lookup -> upload -> Gemini Code Insight verdict (benign auto-approve, suspicious warn, malicious block) -> daily re-scan; OpenClaw itself says it will not catch prompt-injection payloads. alonw0/secure-skills (TypeScript fork of vercel-labs/skills, 13 stars, no license of its own) shows the integration pattern: ~81 local regex rules + correlation in `src/scanner.ts`, a 'URL transparency' prompt listing every external URL before install, skills.sh audit lookup and optional VirusTotal hash lookup in `src/vt.ts`.

### Snyk's and OWASP's taxonomies give ready-made names for the mutable-target finding class [high]
Snyk agent-scan distinguishes `unverifiable_dependencies` (W012: 'fetches executable code or instructions from remote URLs at runtime, so its behavior can change independently of the installed skill', remediation 'bundle and verify dependencies locally'), `third_party_content_exposure` (W011: fetch-and-act on public/user-controlled content), `suspicious_download_url` (E005), and W021 hidden Unicode. OWASP AST05 mitigations are all deterministic and implementable by a package manager: (1) record a content hash for every external document at review time and refuse drifted/unpinned content, (2) prefer inlining/snapshotting external docs into the package at publish time, (3) allowlist permitted reference domains/URL globs, (4) audit references transitively, (5) keep a fleet-wide inventory of which skill references which source, (6) rescan continuously. AST07: pin installs to immutable sha256 content hashes, require signatures on updates, freeze mode, human approval for updates, inventory with version/hash/last-verified. ATR maps its rug-pull rule to MITRE ATLAS AML.T0109 'AI Supply Chain Rug Pull' and OWASP 'AST06:2026 - Rug Pull / Supply Chain' (note: that AST numbering in the ATR rule does not match the published OWASP v1.0 list, where rug pull content lives under AST05/AST07; use the OWASP repo as the authority).
